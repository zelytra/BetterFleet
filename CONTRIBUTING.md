# Contributing to BetterFleet

Thanks for wanting to make BetterFleet better. It is a free, open-source project run by volunteers,
and every bug report, translation and pull request helps crews land on the same server.

Everyone taking part is expected to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Ways to help

- **Report a bug.** Open an issue with the *Bug report* form. For server detection problems, send a
  report from the app too (report page, *Capture (in game)* while on a server, then
  *Submit report*): it carries the logs and the network scan we need.
- **Suggest a feature.** Use the *Feature request* form, and start from the need rather than the
  solution.
- **Translate.** Translations happen on [Crowdin](https://translate.betterfleet.fr), not in pull
  requests. French is translated by humans only; the other languages start as machine translations
  and are corrected there, so a native review is always welcome.
- **Write code.** Read on.
- **Ask a question.** The [Discord](https://discord.gg/sHPp5CPxf2) is the place.

**Found a security vulnerability?** Do not open an issue or a pull request: follow the
[security policy](SECURITY.md) and report it privately.

## The project in one minute

| Path | What it is | Stack |
|---|---|---|
| `webapp/` | The desktop app (Windows and Linux) | Tauri v2 (Rust) + Vue 3 + TypeScript |
| `backend/` | Sessions (WebSocket), REST, statistics | Quarkus, Java 17 |
| `website/` | Public site and statistics dashboard | Vue 3 + TypeScript |
| `deployment/` | Compose files, Helm chart, Keycloak realm | |

Deeper documentation (architecture, per-module guides, known traps, step-by-step recipes) lives in
[`CLAUDE.md`](CLAUDE.md) and [`.claude/docs/`](.claude/docs/README.md). It is written for anyone
working in the repository, human or AI agent: read [`gotchas.md`](.claude/docs/gotchas.md) before
touching detection, the overlay or `SessionManager`.

## Setting up

You need **Node.js**, **JDK 17**, **Docker**, and **Rust** with the Tauri v2 prerequisites if you
work on the desktop shell.

```bash
# Backing services (Postgres, Keycloak): infra only, not the app
docker compose -f deployment/dev/docker-compose.yml up -d

# Backend, live reload on :8080
cd backend && ./mvnw compile quarkus:dev

# Desktop app (starts its own Vite dev server)
cd webapp && npm install && npm run tauri:dev

# Website on :5174
cd website && npm install && npm run dev
```

The backend's dev configuration already points at the compose ports. On Linux, `tauri:dev` grants
the capture helper `CAP_NET_RAW` through `sudo setcap`; without it, detection degrades instead of
crashing.

## Before you open a pull request

Run the checks for every module you touched. CI runs them too, only for the modules a pull request
changes, and fails on any of them.

| Module | Checks |
|---|---|
| `webapp/`, `website/` | `npm run build` (the type check), `npm run test`, `npm run lint:check`, `npm run prettier:check` |
| `backend/` | `./mvnw test` (in-memory H2, no database needed) |
| `webapp/src-tauri/` | `cargo test`, after `npm run build` in `webapp/` (the crate embeds the built frontend); `cargo clippy --all-targets` is not in CI but expected clean |

**A visible change must be looked at.** CI type-checks and runs the tests, but it cannot see a broken
layout: render what you changed and check it with your own eyes before asking for review.

**A bug fix comes with a test that fails without it.** Show that failing output in the pull request
("Red first"): it is what proves the test covers the bug.

## How changes are made

- **One branch per issue, one concern per pull request.** Name it `feat/<slug>-<issue>` or
  `fix/<slug>`. Unrelated changes go in separate pull requests, even when they are small.
- **Target `master`.** Pull requests are squash-merged by a maintainer once they are green and
  reviewed.
- **Conventional commit subjects**: `feat(scope): ...`, `fix(scope): ...`, `docs: ...`, with a body
  that explains *why*, not what the diff already shows. The pull request title follows the same
  form, without an issue number (squash-merge appends the pull request number).
- **Fill in the pull request template**: `Closes #N.`, the cause, the fix, what must not change,
  and the exact checks you ran. Never claim a check that did not run; say what you could not test.

## Project rules worth knowing first

- **Translations: only edit `webapp/src/assets/locales/source.json`** (the English original). Add a
  new key to every locale file, in place, without reformatting them; `en.json` is regenerated by CI
  and the other languages come from Crowdin. `Locales.spec.ts` checks that every file has every key.
- **No em-dashes in code comments or documentation**: use a colon, a comma or parentheses.
  User-visible strings may keep them.
- **Tauri is on v2.** Do not bring back v1 configuration shapes, plugin names or signing variables.
- **Backend concurrency**: no blocking I/O while `SessionManager` holds a write lock, and nothing
  blocking on the event loop. The reasons are in [`gotchas.md`](.claude/docs/gotchas.md).
